# wsus-protocol fuzzing

Fuzz harnesses for the `wsus-protocol` crate live in the standalone `fuzz/`
package in wsus-rs and follow the existing conventions: honggfuzz
binaries, harness bodies in a library-style module that is shared with a replay
tool and a plain `cargo test` smoke test, and a corpus under `fuzz/corpus/`
(git-ignored, regenerated by a seed script). The request asked for cargo-fuzz;
the repository already standardises on honggfuzz and `cargo-fuzz` is not
installed here, so the harness bodies are engine independent and can be wrapped
by `libfuzzer_sys::fuzz_target!` if that is preferred later.

## Targets

| Target | Covers |
| --- | --- |
| `wsus_envelope` | `Envelope::decode` for SOAP 1.1 and 1.2, `payload_name`, `must_understand_headers`, `validate_action`, `action_from_content_type` |
| `wsus_fault` | `SoapFault::from_element` for both versions, `to_element`, `encode_fault`, error-code classification, envelopes carrying faults |
| `wsus_xml` | `xml::parse` and `xml::parse_fragments`, plus serializing the results |
| `wsus_wusp` | MS-WUSP request decode (with and without a matching action) and response decode for all ten operations |
| `wsus_wsusss` | MS-WSUSSS request and response decode for all ten operations |
| `wsus_metadata` | `UpdateIndex::parse`, `FragmentIndex::parse`, `merge`, `into_update_index` |
| `wsus_applicability` | `ApplicabilityRules::from_element` and `Expr::parse` over lenient fragments (flags bit 1 clear) or strict documents (set), `evaluate` against no facts, a fake machine and, with flags bit 2, a `RecordedFacts` snapshot loaded from the same bytes; `required_queries`. Oracle: no panic, an `Unknown` result always carries a blocker and a definite one never does |
| `wsus_xpress` | `wsus_protocol::xpress::decode` of arbitrary bytes under small block and total limits (flags bits 0 and 1), then decode(encode(x)) equality for the payload and for anything that decoded |
| `wsus_roundtrip` | Where decode succeeds, `encode(decode(x))` must decode equal: XML trees, envelopes, and every WUSP and WSUSSS request and response, encoded as SOAP 1.1 and 1.2 |

Every input is `[flags, document...]`. Bit 0 of `flags` turns
`Limits::strict_sequence_order` off; the other bits select a message type, SOAP
version or roundtrip area (layout in `fuzz/src/wsus.rs`). All targets use small
limits (64 KiB body, depth 16, 64 array items, 2048 elements) and skip larger
inputs, so each iteration stays fast. Rejection by the decoder is normal; panics,
roundtrip mismatches and hangs are findings.

## Run

```sh
python3 fuzz/seed_wsus.py          # seeds fuzz/corpus/wsus_* from crates/wsus-protocol/tests/fixtures
cargo test --manifest-path fuzz/Cargo.toml --locked --test wsus_smoke
HFUZZ_RUN_ARGS="-n 1 -t 5 -N 10000 --exit_upon_crash" task fuzz -- wsus_wusp
```

Valid targets for `task fuzz --` are `wsus_envelope`, `wsus_fault`, `wsus_xml`,
`wsus_wusp`, `wsus_wsusss`, `wsus_metadata`, `wsus_applicability`, `wsus_roundtrip` and `wsus_xpress` (the corpus
directory has the same name). Replay a crash with:

```sh
cargo run --manifest-path fuzz/Cargo.toml --locked --bin wsus_replay -- wsus_roundtrip path/to/crash
```

`tests/wsus_smoke.rs` runs every harness over every fixture under all 256 flag
values, and a deterministic xorshift mutation pass (`WSUS_MUTATIONS=n`, default
300 per fixture) that prints the failing input before re-raising any panic. It
is a stand-in for a short campaign, not a substitute for coverage-guided runs.

## Findings (wsus-protocol, not fixed here)

No panic and no hang was found: about 3x10^7 mutated harness executions (300000 mutations per fixture across seven targets) over
the fixtures completed without either. The roundtrip oracle did find
non-panicking defects in `soap::xml`; the harness skips those shapes (and says so
in `fuzz/src/wsus.rs`) so that it can reach further bugs.

1. Namespace declarations are not unescaped. `<a xmlns="x&amp;y"/>` parses to
   namespace `x&amp;y` (and `&#13;`, `&lt;` likewise); the serializer escapes
   it again, giving `xmlns="x&amp;amp;y"`, so the namespace grows with every
   roundtrip.
2. Empty element names are accepted. `<a>< /></a>` (also `<a><\t/></a>`) parses
   to an element with an empty local name, which serializes as `</>`; the
   output then fails to parse.
3. Names with characters XML forbids are accepted, for example `<b:!True/>`
   inside a fragment; the serializer emits them and the result fails to
   re-parse.

Two shapes are normalised by design and the harness accounts for them: an
unqualified fault code gains a `soap:` prefix when re-encoded, and an encoded
fault rebuilds `detail` from the parsed WSUS fields, dropping other detail
content. Parsed fault fields must otherwise survive and a second round must be a
fixed point.

## Scope

These harnesses exercise the parsers and codecs only. The fixtures are
spec-derived, not captured from a server or client, so a clean run says nothing
about interoperability.
