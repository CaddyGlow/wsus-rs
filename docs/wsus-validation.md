## Rules for this ledger

- `Partially validated` means a narrower claim than the row's wording is
  evidenced; the row's Limitations column states exactly which part. It never
  means the row's full claim holds.

- A row may change from `Not validated` only when it links a retained test run
  that identifies exact client and server builds, protocol profile, supported
  operations, evidence, and limitations.
- Our client against our server (pair 3) never validates compatibility with
  Microsoft software. It only supports the integration claims for that pair.
- Specification conformance, sample-repository behavior and mocked servers are
  not compatibility evidence.
- Unsupported categories stay listed as unsupported. A narrower evidenced claim
  replaces a broader claim; it never extends it.
- Evidence must exclude cookies, credentials, keys, signed URLs and sensitive
  registration data. Record hashes of raw captures instead.
- When a validation claim changes, update this file and the inventory in the
  same change.

## Applicability differential run (C32, C34)

Leaf level (C35): see the exact command in inventory 12.8 (`applicability_leaf_differential.rs`, needs `search2.json` from a native COM search on the same guest state and the native scan).

Prerequisites: the stored revisions (`WSUS_REAL_REVISIONS`, default
`~/vm-lab/wsus-m0/client-run5/state/meta/revisions`, read-only) and a disposable
Windows 11 guest. Nothing below changes the guest.

1. On the host, list the queries the catalog needs (about 20,000, almost all MSI
   products):

   ```sh
   python3 scripts/wsus/applicability-queries.py --out queries.json
   ```

2. Copy `queries.json` and `scripts/wsus/collect-facts.ps1` to the guest and run
   the script as SYSTEM in the 64-bit Windows PowerShell 5.1 (the Windows Update
   Agent is a SYSTEM service; a 32-bit shell is refused because file system
   redirection would change the file facts). Smoke test first:

   ```powershell
   psexec -accepteula -s powershell.exe -ExecutionPolicy Bypass -File C:\work\collect-facts.ps1 -Queries C:\work\queries.json -Out C:\work\facts-smoke.json -Limit 50
   psexec -accepteula -s powershell.exe -ExecutionPolicy Bypass -File C:\work\collect-facts.ps1 -Queries C:\work\queries.json -Out C:\work\facts.json
   ```

   The script prints the counts of known, absent and unavailable answers; note
   them (a large `unavailable` count means a collector problem, not a verdict).
3. On the SAME guest state run a native Windows Update scan against the real WSUS and
   capture its `SyncUpdates` requests and responses (Xpress-decoded) as
   `native-diff/scan/NNNNNN/{request,response}.body`; the server-local ids of a run
   are valid only with the responses of that run (the stored revisions use other
   ids). Copy `facts.json` back and run the ignored differential test with the
   LAST request that carries the full installed list:

   ```sh
   WSUS_FACTS_JSON=/path/to/facts.json WSUS_NATIVE_FIXTURES=/path/to/native-diff \
     WSUS_NATIVE_REQUESTS=scan/000054 \
     cargo test -p wsus-protocol --test applicability_differential -- --ignored --nocapture
   ```

   Optional: `WSUS_NATIVE_REQUESTS=set/000001,set/000013` (united lists, one set),
   `WSUS_DIFF_SCOPE=all` (every candidate revision, not only non-leaf ones and
   the ids the client listed), `WSUS_DIFF_REPORT=/path/report.json`. The test
   prints one line per update (`Agree`, `Agree(weak)`, `Disagree`, `Unknown`,
   `NotComparable`, `SUSPECT`) and a summary, writes the JSON report, and fails
   when any update the client reported installed gets a definite False.
   Unknown is never counted as agreement.
4. Record the guest build and UBR, the time of the facts, the native request used,
   and the summary in the revision log before moving C32 or C34. The comparison
   is only meaningful if the guest is in the state the native client had when it
   sent that request.
